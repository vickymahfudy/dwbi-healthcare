\section{Arsitektur DAG (Directed Acyclic Graph)}
 
Apache Airflow bertindak sebagai mesin pengatur dan penjadwal utama (\textit{enterprise orchestrator}) untuk mengotomatisasi seluruh siklus data dalam sistem DWBI rumah sakit ini. Di dalam Airflow, rangkaian alur kerja didefinisikan sebagai \textbf{Directed Acyclic Graph (DAG)} bernama \texttt{02\_healthcare\_data\_pipeline}. Karakteristik \textit{"directed"} menandakan alur eksekusi memiliki arah ketergantungan yang jelas dari awal hingga akhir, sedangkan \textit{"acyclic"} menjamin bahwa tidak ada tugas yang berjalan berulang atau membentuk putaran tak berujung (\textit{infinite loop}).
 
Konfigurasi parameter operasional dan manajemen risiko dari DAG ini dirancang menggunakan argumen bawaan (\textit{default args}) sebagai berikut:
 
\begin{itemize}
    \item \textbf{Owner (\texttt{kelompok\_healthcare}):} Digunakan sebagai identitas pengelola aset \textit{pipeline} untuk mempermudah kategorisasi, audit log, dan pemfilteran pada dasbor Web UI Airflow.
    \item \textbf{Depends on Past (False):} Keberhasilan eksekusi \textit{pipeline} hari ini tidak digantungkan pada status keberhasilan eksekusi hari sebelumnya, sehingga mencegah kemacetan massal (\textit{data blocking}).
    \item \textbf{Retries (1) \& Retry Delay (2 menit):} Jika sebuah \textit{task} gagal akibat masalah jaringan atau database PostgreSQL yang sedang sibuk, Airflow akan menjadwalkan ulang eksekusi otomatis satu kali lagi setelah jeda 2 menit.
    \item \textbf{Schedule Interval (None) \& Catchup (False):} \textit{Pipeline} dikonfigurasi untuk berjalan berdasarkan pemicu manual (\textit{Manual Trigger}). Penonaktifan \textit{catchup} mencegah Airflow melakukan eksekusi susulan (\textit{backfilling}) terhadap jadwal historis masa lalu.
\end{itemize}
 
\section{Topologi dan Penjelasan \textit{Task Dependencies}}

\textit{Pipeline} dipecah menjadi 6 \textit{task} diskrit yang dikelola oleh dua operator
utama: \texttt{BashOperator} untuk mengeksekusi perintah di lingkungan \textit{shell} Linux,
dan \texttt{PythonOperator} untuk mengeksekusi fungsi Python di dalam memori proses Airflow.
Keenam \textit{task} diikat menggunakan operator dependensi sekuensial linear (\texttt{>>}),
membentuk urutan kronologis sebagai berikut:

\begin{lstlisting}[language=Python, caption=Definisi alur dependensi keseluruhan pipeline]
task_generate_data >> task_ingest_data >> task_auto_generate_models \
    >> task_dbt_run >> task_dbt_test >> task_dbt_docs >> task_dbt_docs_serve
\end{lstlisting}

% -------------------------------------------------------
\subsection*{Task 1: \texttt{run\_data\_generator} (BashOperator)}

Airflow memicu lingkungan \textit{shell} Linux untuk menjalankan skrip pembuat data sintetik
secara langsung melalui interpreter Python yang tersedia di dalam kontainer Docker.

\begin{lstlisting}[language=Python, caption=Definisi Task run\_data\_generator]
task_generate_data = BashOperator(
    task_id='run_data_generator',
    bash_command='python /opt/airflow/data_generator/src/generator.py',
)
\end{lstlisting}

Airflow memastikan skrip \texttt{generator.py} selesai dieksekusi sepenuhnya dan menghasilkan
tiga file CSV (\texttt{source\_pasien.csv}, \texttt{source\_dokter.csv},
\texttt{source\_kunjungan.csv}) di direktori \textit{shared storage}
\texttt{/opt/airflow/data\_generator/output} sebelum mengizinkan aliran data berpindah ke
\textit{task} berikutnya.

% -------------------------------------------------------
\subsection*{Task 2: \texttt{ingest\_csv\_to\_database} (PythonOperator)}

Airflow memanggil fungsi Python \texttt{ingest\_csv\_to\_postgres} secara langsung di dalam
memori proses \textit{worker} untuk memindahkan data dari file \texttt{.csv} ke tabel
relasional PostgreSQL.

\begin{lstlisting}[language=Python, caption=Definisi Task ingest\_csv\_to\_database]
task_ingest_data = PythonOperator(
    task_id='ingest_csv_to_database',
    python_callable=ingest_csv_to_postgres,
)
\end{lstlisting}

Fungsi ini menggunakan \textit{connection string}
\texttt{postgresql+psycopg2://airflow:airflow@postgres:5432/airflow} untuk terhubung ke
PostgreSQL via SQLAlchemy. Data dibaca melalui \textit{DataFrame} Pandas, kemudian ditulis ke
tabel \texttt{src\_pasien}, \texttt{src\_dokter}, dan \texttt{src\_kunjungan} dengan strategi
pemuatan \textit{idempotent}: jika tabel sudah ada, isinya dikosongkan terlebih dahulu
(\texttt{TRUNCATE}) sebelum data baru dimasukkan (\texttt{if\_exists='append'}); jika tabel
belum ada, tabel dibuat otomatis (\texttt{if\_exists='fail'} pada eksekusi pertama). Seluruh
operasi ini dibungkus dalam satu blok transaksi \texttt{engine.begin()} untuk menjamin
konsistensi data.

% -------------------------------------------------------
\subsection*{Task 3: \texttt{auto\_generate\_dbt\_files} (PythonOperator)}

Airflow memanggil fungsi \texttt{auto\_generate\_dbt\_models} untuk mengunduh konfigurasi
model dbt secara dinamis dari repositori GitHub dan membuat seluruh file SQL model secara
otomatis di dalam volume Docker.

\begin{lstlisting}[language=Python, caption=Definisi Task auto\_generate\_dbt\_files]
task_auto_generate_models = PythonOperator(
    task_id='auto_generate_dbt_files',
    python_callable=auto_generate_dbt_models,
)
\end{lstlisting}

Fungsi ini mengunduh file \textit{manifest} YAML dari \textit{raw URL} repositori GitHub
(\texttt{dbt\_manifest.yml}), kemudian mengiterasi setiap entri untuk membuat file
\texttt{.sql} model dbt di direktori \texttt{/opt/airflow/dbt\_project/models/} dengan
sub-folder \texttt{staging}, \texttt{dimensions}, dan \texttt{marts}. Secara bersamaan,
fungsi mendeteksi nama tabel sumber melalui ekspresi reguler pada pemanggilan
\texttt{source()}, lalu secara otomatis menghasilkan file \texttt{sources.yml} agar dbt
dapat mengenali skema PostgreSQL tanpa konfigurasi manual.

% -------------------------------------------------------
\subsection*{Task 4: \texttt{dbt\_run\_transformation} (BashOperator)}

Airflow memerintahkan dbt sebagai \textit{third-party transformation tool} untuk memproses
seluruh model SQL dan membangun struktur \textit{Star Schema} secara nyata di dalam database.

\begin{lstlisting}[language=Python, caption=Definisi Task dbt\_run\_transformation]
task_dbt_run = BashOperator(
    task_id='dbt_run_transformation',
    bash_command=(
        'cd /opt/airflow/dbt_project && '
        'dbt run --target docker_env --profiles-dir .'
    ),
)
\end{lstlisting}

Airflow mengirimkan perintah CLI \texttt{dbt run} yang menginstruksikan dbt untuk
mengompilasi dan mengeksekusi seluruh model SQL mulai dari lapisan \textit{staging},
\textit{dimensions}, hingga \textit{marts}, sehingga menghasilkan tabel fakta dan dimensi
(\textit{Star Schema}) yang persisten di dalam PostgreSQL.

% -------------------------------------------------------
\subsection*{Task 5: \texttt{dbt\_data\_quality\_test} (BashOperator)}

Airflow mengeksekusi rangkaian pengujian kualitas data yang telah didefinisikan dalam skema
YAML dbt sebelum hasil transformasi dinyatakan siap dikonsumsi oleh lapisan analitik.

\begin{lstlisting}[language=Python, caption=Definisi Task dbt\_data\_quality\_test]
task_dbt_test = BashOperator(
    task_id='dbt_data_quality_test',
    bash_command=(
        'cd /opt/airflow/dbt_project && '
        'dbt test --target docker_env --profiles-dir .'
    ),
)
\end{lstlisting}

Perintah \texttt{dbt test} mengeksekusi seluruh pengujian integritas yang telah
dikonfigurasi, mencakup pemeriksaan \texttt{unique}, \texttt{not\_null},
\texttt{accepted\_values}, dan \texttt{relationships} antar tabel. Apabila salah satu
pengujian menghasilkan kegagalan, Airflow akan menandai \textit{task} ini dengan status
\textit{Failed} (ditampilkan dalam warna merah pada UI) dan menghentikan seluruh
\textit{pipeline} secara otomatis, sehingga data yang tidak valid tidak sampai ke lapisan
pelaporan.

% -------------------------------------------------------
\subsection*{Task 6: \texttt{dbt\_generate\_docs} (BashOperator)}

Airflow mengeksekusi proses pembangkitan dokumentasi dbt secara otomatis setelah seluruh
pengujian kualitas data dinyatakan lulus.

\begin{lstlisting}[language=Python, caption=Definisi Task dbt\_generate\_docs]
task_dbt_docs = BashOperator(
    task_id='dbt_generate_docs',
    bash_command=(
        'cd /opt/airflow/dbt_project && '
        'dbt docs generate --target docker_env --profiles-dir .'
    ),
)
\end{lstlisting}

Perintah \texttt{dbt docs generate} mengompilasi seluruh metadata model, kolom, deskripsi,
dan hasil pengujian menjadi artefak statis berupa file \texttt{manifest.json} dan
\texttt{catalog.json} yang menjadi fondasi portal dokumentasi interaktif dbt.

% -------------------------------------------------------
\subsection*{Task 7: \texttt{dbt\_serve\_docs} (BashOperator)}

Airflow menjalankan server dokumentasi dbt di \textit{background} agar \textit{task} dapat
langsung berstatus \textit{Success} tanpa memblokir proses Airflow.

\begin{lstlisting}[language=Python, caption=Definisi Task dbt\_serve\_docs]
task_dbt_docs_serve = BashOperator(
    task_id='dbt_serve_docs',
    bash_command='''
        fuser -k 8081/tcp || true
        cd /opt/airflow/dbt_project && \
        nohup dbt docs serve --port 8081 \
            > /opt/airflow/logs/dbt_docs.log 2>&1 &
    ''',
)
\end{lstlisting}

\textit{Task} ini terlebih dahulu memeriksa apakah \textit{port} 8081 sudah aktif; jika ya,
proses lama dimatikan via \texttt{fuser -k} sebelum server baru dijalankan. Server dbt
kemudian dijalankan menggunakan \texttt{nohup ... \&} agar berjalan sebagai proses
\textit{daemon} yang tidak bergantung pada siklus hidup proses Airflow. Portal dokumentasi
dapat diakses melalui \texttt{http://localhost:8081} setelah \textit{task} ini berhasil.
