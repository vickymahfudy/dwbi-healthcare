\subsubsection{Detail Dimension Table Utama}
 
\texttt{Dim\_Pasien} merupakan dimensi paling kaya atribut dengan 34 kolom flag komorbiditas biner ditambah atribut demografis. Dimensi ini menggunakan SCD Tipe 2 untuk melacak perubahan status klinis pasien dari waktu ke waktu (misalnya: perubahan kategori usia, penambahan diagnosis komorbiditas baru). Setiap perubahan menghasilkan baris baru dengan kolom \texttt{effective\_date}, \texttt{expiry\_date}, dan \texttt{is\_current} untuk menjaga histori lengkap.
 
\texttt{Dim\_Waktu} dibangun dari kolom \texttt{Procedure\_Date} dengan hierarki: Tanggal $\to$ Minggu $\to$ Bulan $\to$ Kuartal $\to$ Tahun. Dimensi ini bersifat statis (SCD Tipe 0) karena nilai tanggal tidak pernah berubah setelah dicatat.
 
\texttt{Dim\_Prosedur} memuat 5 kode prosedur unik (CPT-80053, CPT-70450, CPT-71045, CPT-93000, ICD10-0DTJ) dengan deskripsi dan kategorinya. Menggunakan SCD Tipe 1 karena perubahan deskripsi prosedur cukup ditimpa langsung tanpa perlu histori.

\section{Perancangan Arsitektur Staging dan Alur ETL}
 
Untuk memastikan data transaksional dapat mengalir dari sistem sumber (file generator) ke dalam \textit{Star Schema} dengan aman dan terstruktur, dirancang sebuah arsitektur \textit{Extract, Transform, Load} (ETL) yang memanfaatkan \textit{Staging Area}.
 
\subsubsection{Konsep dan Fungsi Staging Area}
 
\textit{Staging Area} merupakan area penyimpanan sementara (\textit{buffer zone}) yang menjembatani file CSV sumber dengan repositori akhir Data Warehouse. Penggunaan \textit{staging area} dalam perancangan ini bertujuan untuk:
 
\begin{itemize}
    \item \textbf{Ekstraksi Cepat:} Memindahkan data dari file \texttt{source\_*.csv} ke dalam database relasional secepat mungkin untuk meminimalisasi beban baca pada file sumber.
    \item \textbf{Transformasi \& Standarisasi:} Memvalidasi format tipe data (seperti format tanggal dan angka desimal) sebelum disuntikkan ke skema utama.
    \item \textbf{Pembentukan Surrogate Key:} Tempat pemetaan kunci alami (\textit{Natural Key} seperti \texttt{id\_pasien}) menjadi kunci pengganti numerik (\textit{Surrogate Key}) untuk mempercepat performa \textit{query} OLAP.
\end{itemize}
 
\subsubsection{Pemetaan Tabel Staging}
 
Skema \textit{staging} dirancang dengan prinsip relasi satu-banding-satu (1:1) terhadap file CSV yang dihasilkan oleh Python. Data akan dimuat dengan metode \textit{Truncate and Load} ke dalam tiga tabel \textit{staging} berikut:

\subsubsection{Alur Transformasi ke Star Schema}
 
Setelah data mentah mendarat di tabel \textit{staging}, proses \textit{Transform} dan \textit{Load} akan mendistribusikan data tersebut ke dalam 5 Tabel Dimensi dan 1 Tabel Fakta dengan urutan logis sebagai berikut:
 
\textbf{Langkah 1: Pengisian Tabel Dimensi}
 
Tabel dimensi wajib diisi lebih dahulu untuk menjaga integritas \textit{Foreign Key}.
 
\begin{itemize}
    \item \texttt{Dim\_Waktu}: Sistem mengekstrak nilai \textit{distinct} \texttt{tanggal\_kunjungan} dari \texttt{stg\_kunjungan}, lalu memecahnya menjadi komponen hari, bulan, tahun, dan \textit{weekend flag}.
    \item \texttt{Dim\_Fasilitas} \& \texttt{Dim\_Pembayaran}: Sistem mengambil nilai unik (IGD/Inap/Jalan) dan metode pembayaran (BPJS/Mandiri/Swasta) dari \texttt{stg\_kunjungan}.
    \item \texttt{Dim\_Pasien} \& \texttt{Dim\_Dokter}: Data dari \texttt{stg\_pasien} dan \texttt{stg\_dokter} dipindahkan ke dimensi utama. Pada tahap ini, sistem menghasilkan \textit{Surrogate Key} (\texttt{pasien\_key}, \texttt{dokter\_key}) dan mengevaluasi status perubahan data untuk SCD.
\end{itemize}
 
\textbf{Langkah 2: Pengisian Tabel Fakta}
 
Pembentukan tabel \texttt{Fact\_Kunjungan} dieksekusi melalui \textit{query} JOIN antara \texttt{stg\_kunjungan} dengan kelima tabel dimensi yang telah diperbarui.
 
\begin{itemize}
    \item Sistem mengambil metrik nominal (\textit{Measures}) secara langsung: \texttt{biaya\_konsultasi}, \texttt{biaya\_obat}, \texttt{biaya\_tindakan}, \texttt{biaya\_kamar}, \texttt{total\_biaya}, dan \texttt{lama\_rawat\_hari}.
    \item Sistem melakukan proses \textit{Lookup} pada setiap dimensi untuk mengganti \textit{Natural Key} (misal: \texttt{PSN-00001}) menjadi \textit{Surrogate Key} numerik.
    \item Seluruh kombinasi \textit{Surrogate Key} dan \textit{Measures} disuntikkan sebagai baris baru ke dalam \texttt{Fact\_Kunjungan}.
\end{itemize}
 
\subsubsection{Orkestrasi Pipeline ETL}
 
Proses pergerakan data dari file CSV ke \textit{Staging} hingga ke \textit{Star Schema} akan diotomatisasi secara terjadwal menggunakan Apache Airflow. Hal ini menjamin siklus pembaruan laporan DWBI di rumah sakit berjalan harian secara konsisten tanpa intervensi manual.
